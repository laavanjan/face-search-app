## 1. Where it comes from

All test data is generated by code. **No real photos, face scans, customer uploads or production
embeddings are used** in the repository or its tests.

| Artefact | Generator | How |
|---|---|---|
| Test images | `synthetic_png()`, `synthetic_jpeg_with_exif()` | Pillow `Image.new` flat-colour canvases (no faces, no people). The JPEG variant carries fake EXIF (`Make=SyntheticCam`) to prove metadata stripping. |
| Face embeddings | `synthetic_embedding(seed)` | NumPy `default_rng(seed).standard_normal(512)`, L2-normalised. Same seed = "same person"; different seeds are near-orthogonal (cosine ≈ 0 ± 0.05). |
| Detected faces | `synthetic_face(seed)` | Wraps a synthetic embedding in `face_engine.DetectedFace` with a fixed bbox and scores; injected by patching `face_engine.analyze`. |

Reproduce: `cd backend && pytest` - all fixtures are deterministic.

## 2. Production guard

Synthetic PNGs carry the text chunk `fsa-synthetic=true`. `pipeline.prepare()` rejects any image with
that marker (HTTP 422) unless `SYNTHETIC_DATA_ENABLED=true`, which is `false` by default and set only by
`backend/tests/conftest.py`. Fixtures therefore cannot be ingested into real photo or vector stores.
Verified by `tests/test_pipeline.py::test_synthetic_marker_rejected_in_production`.

## 3. Bias assessment

Random 512-d vectors and blank images contain **none** of the variation that drives face-recognition
error: skin tone, age, gender presentation, disability, facial hair, glasses, pose, occlusion, lighting,
camera and compression. They cannot show whether detection or matching performs equally across groups.

Risk: passing synthetic tests could be mistaken for evidence of accuracy or fairness. Mitigation: this
document, the docstring on the generator, and the rule below.

## 4. Limitations - what synthetic tests do and do not show

Do show: deterministic pipeline behaviour - store/search round-trip, review gates, access control,
deletion, retention, metadata stripping, error handling.

Do **not** show: detection rate, false-match or false-non-match rate, threshold suitability, or any
demographic performance difference. No claim about those may cite these tests.

## 5. Required before relying on accuracy

Before changing `MIN_DET_SCORE`, `MIN_FACE_SIZE`, `SEARCH_MIN_THRESHOLD`, the model, or deploying with
Rekognition, run an evaluation on a **representative, lawfully sourced and consented** evaluation set
and record FMR/FNMR by group in the change record (risk R-03, [change-management.md §3.1](../governance/change-management.md)).
